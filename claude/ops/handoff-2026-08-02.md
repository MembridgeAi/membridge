## What shipped

**v0.2.4 is published and verified.** npm `latest` is `0.2.4`. This was verified
against the registry rather than the repo: installed into a clean prefix, `GET /`
returned 200 `text/html`, the bundle 200 `text/javascript`, and `membridge add`
adopted a project.

    npm view @membridgeai/membridge dist-tags

The alpha gate was three coupled defects. An npm install produced nothing
usable, for three compounding reasons, and fixing any one alone changed nothing
observable.

- **`ui/dist` now ships in the tarball.** `membridge dashboard` previously
  returned 503 telling users to build in a directory the tarball did not
  contain. The Electron app was the only working surface, and it is Apple
  Silicon only.
- **`membridge add` exists.** Before this there was no enrollment path anywhere
  in the product. `ui/src` has zero references to adopt, so the dashboard never
  had one either. It defaults to cwd, takes several paths, and reuses
  `adoptProjects`' per-path reporting.
- **Adoption backfills prior history.** Previously the daemon consumed
  transcript bytes for untracked projects and never re-read them, so adopting a
  project with three weeks of history showed an empty block. A tombstone keeps a
  deliberately deleted project deleted; `membridge add --backfill` overrides.

Measured end to end: 17.3 seconds from install to visible memory.

Also landed: prepack so `npm pack` ships what `npm publish` ships, an em dash
sweep of user-facing copy, the `lib/activity.js` reconciliation, and the
prompt-sharing branch. First release with a Windows build.

## Things that have already cost real time

Read these as rules, not anecdotes. Each one burned hours.

- **A green CI log is not proof a binary is signed.** Verify a
  browser-downloaded asset with `codesign`, `spctl` and `stapler`.
- **A 200 is not proof a download works.** Check the content type. A missing
  GitHub asset redirects to HTML and still returns 200.
- **The repo working is not proof the product works.** Test published artifacts.
- **A local file is not proof it is the file you just published.** Andrew
  verified a stale `MemBridge-arm64.dmg` in Downloads; the fresh one had landed
  as `MemBridge-arm64 (3).dmg`. The mounted volume name carries the version and
  is the cheapest tell.
- **The app in `/Applications` is not proof of what you built.** Three "bugs"
  reported today were all one cause: the running app was 0.2.2.
- **Prove a path end to end before asking Andrew to run it.** The v0.2.4 publish
  took seven attempts because each failure was fixed forward one layer at a
  time. The attempt that worked was the one where the whole sequence was run in
  a clean clone first. That should have been attempt two.

## npm publishing, hard-won

Do not reach for a token. npm began restricting 2FA-bypass tokens in early
August 2026: they can no longer change package, account or org settings, and
lose direct publish around January 2027. There are three independent 2FA gates
(account mode, package publish mode, token type) and a CI job cannot satisfy a
package gate that demands an OTP.

`release.yml` now uses **trusted publishing (OIDC)**, no token, with provenance
automatic. The npm-side Trusted Publisher entry names this repository and the
workflow filename `release.yml`. **Renaming that file breaks publishing** until
the npm config is updated to match.
